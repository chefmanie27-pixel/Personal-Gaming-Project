## Operations
/api/health is liveness. /api/ready returns generic ready/unavailable with a dependency timeout and short cache; it does not certify schema parity or provider health. Request IDs are generated by the server and returned in X-Request-ID. Logs exclude request URLs/queries/headers/body, identifiers and exception messages. Use request IDs for support; restrict log access/retention. No external error tracker or paging destination is configured. Review process/reverse-proxy logs separately for accidental URL/token capture.

SIGINT/SIGTERM stop new scheduling, drain HTTP and the running job, disconnect Prisma, and have a 15-second fail-safe deadline. Configure the host termination grace period above that deadline; verify signals on the actual host. Scheduler batches 100 alerts per 15-minute tick with process-local cursor/backoff/overlap guard. Default-off durable mode now provides a database lease/checkpoint and atomic in-app history; see the activation notes below. A generic external-delivery queue is not implemented, and no distributed external delivery guarantee is claimed.

## Backup and restoration procedure (not executed on existing data)
1. Operator identifies the exact source DB, backup window and an encrypted restricted destination. Use MySQL credentials through an approved option/login-path mechanism, never a password in a command line or committed .env. Include migrations and all private account/library/workspace/journal/social/notification/discussion tables in the logical backup. Record MySQL version, charset, migrations and a checksum. Keep exports outside the repository and configure encryption/retention/access controls.
2. Create an explicitly NEW uniquely named restore database on an isolated local/staging server. Resolve and check its name/URL. Never restore over the configured or production database. Import the backup into that new target with an approved MySQL client configuration.
3. Check migration state, table/row counts, representative private record fidelity, revision fields, foreign keys, ownership/privacy and price timestamps. Use test accounts only for functional acceptance. Record timings, checksums and recovery objectives. A successful fresh migration test is not a backup restoration drill.
4. Obtain separate approval for an operational recovery/cutover. No DROP/reset, production import or destructive rollback is part of this program.

backend/scripts/test-disposable.mjs creates a new unique local database, migrates it and runs fixtures. It never reuses the configured DB and never drops a database. Created scratch databases are retained for inspection; operator cleanup requires exact target review. This verifies migrations/fixtures, not recovery of existing private data.

## Durable alert activation and operations
DURABLE_ALERTS_ENABLED=0 is the default and configured .env was not changed. Review backup/recovery and authorize migration 20261103180000_durable_alerts on the intended existing database before setting 1. It adds DurableAlertJob and AlertDelivery only. Regenerate Prisma client as part of build preparation. Verify schema parity and staging authorization, then enable the flag consistently on every API/worker instance; mixed legacy/durable evaluators are not a supported rollout configuration. Pause the scheduler during a coordinated switch. Disabling the flag restores legacy scheduling but keeps history tables/data; never drop tables or reconstruct historical events as rollback.

With the flag enabled, admin evaluation uses the same durable claim path and respects saved due/backoff times. There is one price-alert job per database. Polling is 5 seconds; renewable leases last 90 seconds using DB UTC time. Every delivery transaction fences the token before writes. Batches checkpoint at 100 alerts; partial passes become due after 1 second, completed passes after 15 minutes. Failures preserve cursor and retry after 15/30/60/120/240 seconds with fixed EVALUATION_FAILED. Inspect DurableAlertJob through restricted operator tooling for nextRunAt, cursor, lease expiry, failures and lastFinishedAt; leaseToken is internal coordination state, not a public API field. Crash recovery reclaims an expired lease and replays the uncheckpointed batch. Unique history records and notification deduplication protect committed deliveries.

This implementation covers in-app delivery only. Notification, lastTriggered and AlertDelivery record commit atomically; opt-out records disabled rather than sending. User-scoped history survives individual alert deletion and cascades on account deletion. No earlier notifications are backfilled. Define data-retention/export policies before production. Tests simulate lease expiry, failed transactions, competing runners and checkpoint replay; actual process-kill, deployment signals, load, restored-backup activation and mixed-instance rollout require staging acceptance. No existing DB migration, deployment, real email/push or private history publication was performed.
